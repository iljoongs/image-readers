# 03. 데이터 저장 구조 및 파일명 규칙

## 폴더 구조
```
<실행 폴더>/.data/
├── {대주제1}/
│   ├── {소주제1}/
│   │   ├── {대주제1}_{소주제1}_001.jpg
│   │   ├── {대주제1}_{소주제1}_002.png
│   │   └── ...
│   └── {소주제2}/
└── {대주제2}/
    └── ...
```

## 파일명 규칙
`{대주제}_{소주제}_{번호}.{확장자}`
- 번호: 3자리 숫자, 1부터 순차 증가 (001, 002, 003...)
- 확장자: 원본 확장자 유지

## 순서-파일명 동기화 (재넘버링) 로직
이미지 순서가 바뀌는 모든 경우(신규 추가, 드래그로 순서 변경, 삭제)에 대해 해당 소주제 폴더 내 파일을 **현재 표시 순서 기준으로 001부터 재넘버링**한다.

처리 순서 예시:
1. 새 순서 목록(ImageItem 리스트)을 확정한다.
2. 임시 파일명(예: `.tmp_{guid}`)으로 전체를 먼저 rename한다 (번호 충돌 방지).
3. 새 순서대로 001, 002, 003... 최종 파일명으로 rename한다.

> 파일이 많아질 경우 매번 전체 재넘버링은 비용이 커질 수 있음 — v1에서는 단순성 우선, 성능 이슈 발생 시 최적화 검토 (`08-open-decisions.md` 참조).

## 지원 이미지 포맷 (1차 제안)
`.jpg`, `.jpeg`, `.png`, `.bmp`, `.gif`, `.webp`

## 주제 이름과 파일명의 관계 (중요)
파일명에 대주제/소주제 이름이 포함되므로, **주제 이름이 변경되면 해당 폴더 내 모든 파일명도 함께 변경**되어야 한다. 상세 절차는 `04-topic-management.md` 참조.

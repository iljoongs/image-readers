# 03. 데이터 저장 구조 및 파일명 규칙

## 데이터 폴더 위치
데이터 폴더는 실행 폴더에 고정되지 않고 **사용자가 최초 실행 시 지정**한다. 지정 경로는 `%APPDATA%\ImageTopicViewer\settings.json`에 저장되어 이후 자동으로 사용된다. 상세 절차는 `02-architecture.md`의 "데이터 폴더 위치" 절 참조.

이 문서 전체에서 `.data`는 이 사용자 지정 데이터 폴더를 가리키는 표기다(실제 폴더명이 `.data`라는 뜻이 아님).

## 폴더 구조
```
{사용자 지정 데이터 폴더}/
├── {대주제1}/
│   ├── {소주제1}/
│   │   ├── {대주제1}_{소주제1}_001.jpg
│   │   ├── {대주제1}_{소주제1}_002.png
│   │   └── ...
│   └── {소주제2}/
└── {대주제2}/
    └── ...
```
(파일마다 확장자가 다를 수 있다 — 아래 "파일명 규칙" 참조.)

## 파일명 규칙
`{대주제}_{소주제}_{번호}.{원본 확장자}`
- 번호: 3자리 숫자, 1부터 순차 증가 (001, 002, 003...)
- 확장자: **원본 이미지의 형식을 그대로 따른다** (아래 "지원 이미지 포맷" 참조). 같은 소주제 폴더 안에서도 이미지마다 확장자가 다를 수 있다.

## 이미지 파일 불러오기 (2026-08-25 추가)
- 소주제 폴더를 열면(연속보기/단일보기 표시 시) 폴더 내 모든 이미지를 **파일명 순서대로** 불러온다.
- 정렬은 **자연 정렬(natural sort)**을 사용한다: 파일명에 포함된 숫자는 문자열이 아니라 실제 숫자 값으로 비교한다. 예: `2.jpg`가 `10.jpg`보다 앞에 온다. 단순 문자열 정렬이면 "1, 10, 2, ..." 순으로 잘못 정렬된다. 대주제/소주제 이름 정렬(하단 정렬 버튼, `04-topic-management.md`)에도 동일한 규칙이 적용된다 — 예: "1화"/"2화"/.../"10화".
- 인식하는 이미지 확장자는 `.png`/`.jpg`/`.jpeg`/`.bmp`/`.gif`/`.tiff`/`.tif`/`.webp`/`.jfif`/`.ico`/`.heic`/`.heif`/`.avif` — 앱이 직접 저장하지 않는 형식(`.webp` 등)이라도 사용자가 폴더에 수동으로 넣은 이미지가 있으면 목록에 포함한다. 다만 WPF가 실제로 디코딩하지 못하는 형식은 로드에 실패해 해당 항목만 건너뛴다(03의 "지원 이미지 포맷" 참조).
- **파일명 규칙은 강제하지 않는다**: 이미 저장돼 있는 파일이 `{대주제}_{소주제}_{번호}` 규칙을 따르지 않는 이름이어도(예: 폴더를 통째로 복사해 넣은 경우) 불러오기 시점에는 이름을 바꾸지 않는다. 새 폴더가 주제 트리에 새로 인식될 때도 동일하게 적용된다.
- **다음 번호 계산**: 이미지를 새로 추가할 때 부여할 번호는 파일 개수가 아니라, 기존 파일명 중 `_숫자` 형태로 끝나는 것들의 **최댓값 + 1**로 계산한다(번호 규칙을 따르지 않는 파일은 계산에서 제외되지만 목록에는 그대로 남는다). 단순히 "파일 개수 + 1"로 계산하면 번호에 빈틈이 있거나 관례를 따르지 않는 파일이 섞여 있을 때 기존 파일과 같은 이름이 생성되어 **덮어써버릴 수 있어** 이렇게 처리한다.
- 순서 변경(드래그)·삭제로 인한 재넘버링은 이 규칙과 별개로 동작한다: 사용자가 명시적으로 순서를 바꾸거나 삭제하면, 그 결과를 반영하기 위해 관련된 파일명은 여전히 재작성된다(아래 "순서-파일명 동기화" 참조).

## 순서-파일명 동기화 (재넘버링) 로직
이미지 순서가 바뀌는 모든 경우(신규 추가, 드래그로 순서 변경, 삭제)에 대해 해당 소주제 폴더 내 파일을 **현재 표시 순서 기준으로 001부터 재넘버링**한다.

처리 순서 예시:
1. 새 순서 목록(ImageItem 리스트)을 확정한다.
2. 임시 파일명(예: `.tmp_{guid}`)으로 전체를 먼저 rename한다 (번호 충돌 방지).
3. 새 순서대로 001, 002, 003... 최종 파일명으로 rename한다.

> 파일이 많아질 경우 매번 전체 재넘버링은 비용이 커질 수 있음 — v1에서는 단순성 우선, 성능 이슈 발생 시 최적화 검토 (`08-open-decisions.md` 참조).

## 지원 이미지 포맷 및 저장 형식 (2026-08-25 갱신 — 이전의 "PNG 통일 변환" 결정을 대체)
확장자 허용 목록 대신 **디코딩 가능 여부**를 기준으로 판단한다: 드롭된 이미지 데이터를 디코딩할 수 있으면 받아들인다. 디코딩에 실패하면 지원하지 않는 이미지로 간주하고 무시 + 안내 메시지를 표시한다.

**저장 형식은 원본 이미지 형식을 따라간다.** 예: 원본이 JPEG면 `.jpg`로, GIF면 `.gif`로 저장한다. 단, 아래 경우는 PNG로 대체 저장한다(파일명의 확장자도 `.png`가 됨):
- 원본이 WPF가 인코딩을 지원하지 않는 형식일 때 (예: `.webp`, `.avif` — 디코딩은 가능해도 재인코딩 인코더가 기본 제공되지 않음).
- 원본 형식 정보를 알 수 없을 때 (예: 클립보드/드래그 데이터가 이미 디코딩된 비트맵으로만 제공되어 원본 파일 확장자를 알 수 없는 경우).

- WPF가 기본 제공하는 인코더(`BitmapEncoder`)로 저장 가능한 형식: `.jpg`/`.jpeg`(JPEG), `.png`(PNG), `.bmp`(BMP), `.gif`(GIF), `.tiff`/`.tif`(TIFF). 이 목록에 없는 확장자는 전부 PNG로 대체된다.
- 최소 지원 예상 입력(디코딩) 포맷: `.jpg`, `.jpeg`, `.png`, `.bmp`, `.gif`, `.tiff` — WPF 기본 `BitmapDecoder`가 네이티브로 디코딩 가능.
- `.webp`, `.avif`, `.heic`, `.heif` 등은 WPF 기본 디코더가 지원하지 않는다. 폴더 불러오기 목록에는 표시되지만(위 "이미지 파일 불러오기" 참조) 실제로는 디코딩에 실패해 건너뛴다 — 입력 단계에서부터 지원하려면 별도 디코더 라이브러리(예: 서드파티 WIC 코덱, SkiaSharp 등) 추가가 필요하다 (구현 시점에 포함 여부 확인).

## 주제 이름과 파일명의 관계 (중요)
파일명에 대주제/소주제 이름이 포함되므로, **주제 이름이 변경되면 해당 폴더 내 모든 파일명도 함께 변경**되어야 한다. 상세 절차는 `04-topic-management.md` 참조.

## 압축 파일(.zip) 기반 소주제 (2026-08-26 추가)
소주제는 폴더뿐 아니라 **`.zip` 압축 파일**일 수도 있다. 대주제 폴더 바로 아래에 있는 `.zip` 파일은 파일명(확장자 제외)을 소주제 이름으로 하는 소주제로 인식된다.

```
{데이터 폴더}/
└── {대주제}/
    ├── {소주제1}/              ← 폴더 기반 소주제 (기존 방식)
    │   └── {대주제}_{소주제1}_001.png
    └── {소주제2}.zip           ← 압축 기반 소주제
        ├── 001.png
        └── 002.jpg
```

- **용도**: 압축 파일은 앱이 만드는 게 아니라 **사용자가 탐색기 등에서 직접 만들어 대주제 폴더에 넣는 것**이다. 앱은 압축을 풀지 않고 그 안의 이미지를 바로 읽어 보여준다(꿀뷰 등 만화 뷰어와 동일한 방식).
- **내부 이미지 파일명 규칙**: 소주제 이름이 이미 압축 파일명 자체에 담겨 있으므로, 내부 이미지는 **번호만** 쓴다(`001.png`, `002.jpg`처럼). `{대주제}_{소주제}_{번호}` prefix는 붙이지 않는다.
- **읽기 전용**: 압축 기반 소주제는 이미지 추가(드래그드롭)·순서 변경(드래그)·개별 이미지 삭제가 모두 비활성화된다. 드래그드롭 시 드롭 자체가 거부되고(커서에 "불가" 표시), 개별 삭제를 시도하면 안내 메시지가 뜬다.
- **소주제 자체의 이름변경/삭제는 그대로 동작한다**: 이름변경은 `.zip` 파일명만 바꾸고(내부 파일명은 번호만이라 다시 쓸 게 없다), 삭제는 파일 전체를 휴지통으로 이동한다(`RecycleBin.Send`는 파일/폴더 모두 지원).
- **이미지 읽기 순서**: 압축 파일 안 항목도 자연 정렬(위 "이미지 파일 불러오기" 참조)로 정렬해서 보여준다.
- **손상된 압축 파일**: 열 수 없으면 빈 소주제로 취급한다(오류로 앱이 죽지 않음).
- 대주제 폴더 하위에서 폴더명과 `.zip` 파일 베이스네임은 같은 "소주제 이름 공간"을 공유한다 — 즉 폴더 "10화"와 `10화.zip`이 동시에 존재할 수 없다(이름 중복 검증 대상에 압축 파일도 포함).

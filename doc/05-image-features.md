# 05. 이미지 기능 (드래그드롭 추가 / 순서 변경)

## 이미지 추가 (외부 → 페이지)
- 탐색기, 웹 브라우저 등 외부에서 이미지를 페이지 영역으로 드래그드롭하면 추가된다.
- 드롭된 이미지를 디코딩하여 `.data/{대주제}/{소주제}/` 폴더에 **원본 형식 그대로 저장**하고(예: JPEG는 `.jpg`로), 원본이 로컬 파일이었다면 그 원본 파일은 삭제한다. (단순 파일 이동이 아니라 "디코딩 → 원본 형식으로 재인코딩 → 원본 삭제"이며, 사용자 입장에서는 이동과 동일하게 보인다.) WPF가 인코딩을 지원하지 않는 형식(`.webp` 등)이거나 원본 형식을 알 수 없는 경우(브라우저의 비트맵 데이터 등)는 PNG로 대체 저장한다.
- 원본이 로컬 파일이 아니라 웹 브라우저 등이 제공하는 이미지 데이터/임시 파일인 경우도 동일하게 디코딩 후 저장한다(가능하면 원본 파일명의 확장자를 따름). 다만 이 경우 삭제할 원본 파일이 없다.
- 디코딩 가능 여부로 지원 여부를 판단하며, 디코딩 실패 시 무시 + 안내 메시지 표시 (`03-data-storage.md`의 "지원 이미지 포맷 및 저장 형식" 참조).
- 여러 파일을 한 번에 드래그하는 경우: 드롭된 순서(또는 파일 탐색기가 제공하는 순서)대로 뒤에 순차 추가.

## 이미지 순서 변경 (페이지 내)
- 페이지 내 이미지를 드래그하여 다른 위치로 놓으면 순서가 바뀐다.
- 순서 변경 즉시 `03-data-storage.md`의 재넘버링 로직이 실행되어 파일명이 갱신된다.
- 드래그 중 시각적 피드백(삽입 위치 표시선 등) 필요.

## 이미지 삭제 (개별)
- 페이지 내 개별 이미지를 우클릭 메뉴 또는 `Delete` 키로 삭제할 수 있다.
- 삭제 시 확인 다이얼로그를 표시한다.
- 확인 시 해당 이미지 파일을 **Windows 휴지통으로 이동**하고(영구 삭제 아님), `03-data-storage.md`의 재넘버링 로직을 실행하여 남은 이미지들의 파일명을 001부터 재정렬한다.

## 압축(.zip) 기반 소주제는 읽기 전용
소주제가 폴더가 아니라 `.zip` 압축 파일이면(`03-data-storage.md` 참조), 위의 추가/순서 변경/개별 삭제가 전부 비활성화된다:
- 드래그드롭 시 드롭 자체가 거부된다(마우스 커서에 "불가" 표시, 드롭 이벤트가 발생하지 않음).
- 페이지 내 드래그로 순서를 바꾸려 해도 아무 일도 일어나지 않는다.
- 개별 이미지 삭제(우클릭/Delete)를 시도하면 "압축 파일 안의 이미지는 삭제할 수 없습니다" 안내 메시지가 뜨고 삭제되지 않는다.

소주제 자체의 이름변경/삭제(폴더/파일 단위)는 압축 기반 소주제에도 동일하게 적용된다 — `04-topic-management.md` 참조.

## 예외 처리
- 같은 파일명이 이미 `.data` 폴더에 존재하는 경우: 재넘버링 로직이 임시 파일명을 거치므로 일반적으로 충돌 없음. 다만 원본 이동 시 대상 폴더에 동일 파일명이 우연히 존재할 경우 자동으로 다음 번호 할당.
- 이동 실패(파일 잠금 등) 시 사용자에게 오류 알림, 원본은 그대로 유지.
